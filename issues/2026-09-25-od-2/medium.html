Тенденції тижня

Anthropic просувалася одразу на двох фронтах: новий флагман (Opus 5.5) з вікном контексту 1M токенів за замовчуванням і рівнем швидкого інференсу для агентних задач, чутливих до затримки, тоді як Claude Code продовжував отримувати дрібні виправлення ергономіки термінала та посилення MCP. Інструменти для розробки загалом рухаються від генерації коду до контролю після мержу: Rollouts і Security Review в Cursor відстежують код після його випуску, а не до. CodeQL від GitHub продовжує розширювати підтримку мов для статичного аналізу. Інструментарій MCP дозріває, але залишається крихким: перевірки валідації з'являються паралельно з реальною партією відкритих багів у сесіях та OAuth.

Головне

Claude Opus 5.5 виходить із контекстом 1M за замовчуванням

Що з'явилося

Anthropic випустила Claude Opus 5.5 для довготривалих агентних задач з кодом, з вікном контексту 1M токенів увімкненим за замовчуванням, максимум 128k вихідних токенів і постійно активним адаптивним мисленням, за ціною $4/$20 за MTok.

Чому це важливо

Вікно на 1M токенів без beta-заголовка і без надбавки в ціні змінює те, що вміщується в одну агентну сесію: цілі великі репозиторії, довгі ланцюжки використання інструментів або повний огляд кодової бази без ручного скорочення контексту.

Як використати

Встановіть model у значення claude-opus-5-5 в API або в конфігурації моделі Claude Code; для вікна 1M beta-заголовок не потрібен. Слідкуйте за деградацією точності при великій кількості токенів (context rot) і використовуйте кешування підказок для контролю витрат, оскільки множники кешування додаються до іншого ціноутворення.

Fast mode вдвічі пришвидшує вивід Opus за додаткову ціну

Що з'явилося

Дослідницький preview-режим 'fast mode' для Opus 5.5, Opus 5 та Opus 4.8 забезпечує до 2.5x більше вихідних токенів за секунду через beta-заголовок, приблизно за подвійною стандартною ціною за токен.

Чому це важливо

Ті самі ваги моделі та якість, просто швидший потоковий вивід — корисно, коли вузьким місцем є затримка, а не інтелект, наприклад в інтерактивних сесіях кодування чи живих демонстраціях.

Як використати

Встановіть speed: "fast" з beta-заголовком fast-mode-2026-02-01 у виклику messages.create. Перевіряйте response.usage.speed, щоб підтвердити, яка швидкість застосована, і встановіть max_retries=0, якщо хочете самостійно обробляти помилки 429 і переходити на стандартну швидкість.

Cursor додає боти для перевірки після деплою та безпеки

Що з'явилося

Cursor запустив двох ботів: Rollouts відстежує розгорнуті зміни за логами/метриками/трейсами для кожного середовища і позначає регресії, а Security Review публікує один коментар до PR щодо вразливостей, які можна експлуатувати, як-от ін'єкції, обхід автентифікації та секрети.

Чому це важливо

Переносить агентний контроль за межі мержу PR у моніторинг продакшену та адверсаріальний огляд коду — прогалину, яку більшість AI-інструментів для розробки не покривають, оскільки вони зупиняються на генерації коду чи базовому огляді.

Як використати

Безпосередньо недоступно без плану Cursor Teams/Enterprise; читачеві на безкоштовних/споживчих тарифах варто натомість вивчити робочий процес — план ризиків на основі diff, а потім перевірку логів, ініційовану деплоєм — і відтворити його за допомогою хука Claude Code разом із запланованою автоматизацією.

Валідатор плагінів тепер виявляє некоректну конфігурацію MCP

Що з'явилося

claude plugin validate тепер позначає записи в .mcp.json, які мовчки не завантажилися б, незадекларовані посилання ${user_config.*} та небезпечні URL.

Чому це важливо

Раніше неправильна конфігурація MCP-сервера мовчки давала збій під час виконання; виявлення цього на етапі валідації економить час на налагодженні загадки 'інструмента просто немає', що особливо актуально з огляду на реальні відкриті баги, пов'язані з обробкою сесій MCP та OAuth.

Як використати

Запускайте claude plugin validate для будь-якого plugin чи .mcp.json перед розповсюдженням або комітом змін. Поєднайте з git pre-commit хуком, щоб зламані записи MCP ніколи не потрапляли у спільну гілку.

Auto mode за замовчуванням використовує серверний класифікатор моделі

Урок тижня

Керування компромісами між контекстом і швидкістю в Opus 5.5

Вікно контексту на 1M токенів у Claude Opus 5.5 увімкнене за замовчуванням, без потреби в beta-заголовку, але більший контекст не безкоштовний: точність деградує зі зростанням кількості токенів — це явище Anthropic називає context rot. Практична навичка полягає в тому, щоб курувати те, що залишається в контексті, а не скидати туди все підряд. Окремо, fast mode обмінює приблизно 2x ціни на до 2.5x більше вихідних токенів за секунду — це чистий важіль затримки, а не інтелекту, оскільки використовуються ті самі ваги моделі. Ці дві функції вирішують різні проблеми: розмір вікна контексту контролює, скільки модель може враховувати; fast mode контролює, наскільки швидко вона видає вивід у потоковому режимі. Для агентної роботи з кодом хороший патерн — тримати контекст компактним завдяки цілеспрямованому скороченню чи стисненню, навіть коли доступні 1M токенів, і залишати fast mode для інтерактивних, чутливих до затримки моментів, як живі демонстрації чи парні сесії, а не для великих пакетних задач, де стандартне ціноутворення економічніше.

Вправа на 15 хвилин

Надішліть один і той самий запит на кодування до Claude Opus 5.5 двічі через API: один раз зі стандартною швидкістю, інший раз зі speed: "fast" та beta-заголовком fast-mode-2026-02-01. Порівняйте response.usage.speed, output_tokens і фактичний час виконання. Потім візьміть довгу історію розмови і вручну видаліть нерелевантні ходи перед наступним запитом, зафіксувавши, чи покращується якість чи фокус відповіді порівняно з надсиланням повної історії.
