Тенденції тижня

Оркестрація перейшла від одного агента в терміналі до багатьох агентів, якими керують програми. Dynamic workflows з'явилися в Managed Agents API у бета-версії, а Claude Code отримав compaction для кожного subagent і єдине перевизначення model для агентів workflow. Інструменти спостережуваності покращилися: час виконання hooks і підказки про помилки в frontmatter полегшують налагодження власних конфігурацій. Еталонні MCP servers досягли версії 1.0 з великою кількістю виправлень надійності. Типові налаштування дозволів і лімітів контексту продовжують змінюватися, тому перевіряйте їх після кожного оновлення.

Головне

Managed Agents тепер можуть писати й запускати dynamic workflows (бета)

Що з'явилося

Агент Managed Agents може написати workflow — програму, яка поетапно запускає багатьох агентів і об'єднує результати. Вона виконується на сервері як workflow run. Вмикається через поле multiagent із бета-заголовком managed-agents-2026-04-01.

Чому це важливо

Для subagents головний агент має прочитати кожен звіт і вирішити, що робити далі. Workflow передає контекст програмно, тож основний потік залишається вільним для розмови з користувачем і звітування про прогрес. Підходить для аудитів, міграцій і глибоких досліджень.

Можливості

Масовий перегляд документів, міграції в межах усієї кодової бази, перехресна перевірка досліджень і навчальні демонстрації патернів fan-out та fan-in. Клієнтські завдання, як-от аудит сотень договорів чи сторінок, стають одним тривалим завданням, за яким можна стежити, замість ручного циклу.

Як використати

Установіть для поля multiagent агента значення {"type": "multiagent_20261001", "workflows": {"type": "enabled"}} і надсилайте бета-заголовок managed-agents-2026-04-01. У системному промпті агента вкажіть, коли починати запуск. Стежте за подіями workflow_run.* у потоці сесії. Спершу задайте бюджет сесії, адже кожен агент у запуску витрачає токени.

Одна змінна середовища закріплює model для всіх агентів workflow

Що з'явилося

CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL запускає всіх агентів workflow на одній model, тоді як інші subagents зберігають власні model.

Чому це важливо

Workflow може розгалужуватися на багатьох агентів, тож вартість залежить від використаної model. Один перемикач дає змогу віддати масову роботу дешевшій model без редагування кожного визначення subagent.

Можливості

Запускайте широкі аудити чи пакетні перегляди на меншій model, а основну сесію залишайте на потужнішій. Корисно під час навчання, коли для демонстрації в класі потрібна передбачувана вартість.

Як використати

Перед запуском workflow задайте для CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL назву model у профілі оболонки або в env налаштувань. Джерело не вказує допустимого формату значення, тож перегляньте документацію, як називати model, а потім порівняйте вартість і якість на невеликому запуску.

Subagents можуть стискати контекст раніше завдяки autoCompactWindow

Що з'явилося

autoCompactWindow тепер приймається у frontmatter subagent і визначеннях --agents, тож subagent стискає контекст до того, як заповниться вікно основної розмови.

Чому це важливо

Тривалі subagents можуть тримати менше контексту й залишатися сфокусованими, а не успадковувати розмір основного вікна. Це керування тиском контексту окремо для кожного агента.

Можливості

Довгі subagents для досліджень чи перегляду, які виконують багато кроків у циклі, можна тримати легкими. Викладачі можуть показати, як розмір контексту впливає на поведінку агента.

Як використати

Додайте autoCompactWindow до frontmatter subagent або до JSON-визначення --agents. Джерело не вказує одиниць виміру чи допустимого діапазону, тож спершу перегляньте документацію. Уникайте дуже малих значень: у відкритій issue повідомляють про помилки thrashing, які знищують subagents із малим вікном.

Урок тижня

Контроль вартості multi-agent fan-out

Fan-out перетворює одне завдання на багато викликів агентів, тож витрати й контекст ростуть разом із кількістю агентів. У змінах цього тижня є три важелі. Перший — обмеження витрат: Managed Agents рекомендує бюджет сесії, бо кожен агент у запуску workflow витрачає токени. Другий — вибір model для кожного шару: у Claude Code CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL задає одну model для всіх агентів workflow, а інші subagents зберігають свої. Третій — обмеження контексту на агента: frontmatter subagent приймає autoCompactWindow, проте відкриті issues повідомляють про проблеми з малими значеннями, тож перевіряйте, перш ніж покладатися на це. Метод такий: спершу запустіть невеликий зріз — десять елементів, а не сотні. Виміряйте токени, час і якість результату, а потім змінюйте по одному важелю. Записуйте, який важіль на яке число вплинув. Використовуйте дешевшу model для механічних кроків, як-от вилучення полів, а потужнішу — для кроку синтезу. Перед масштабуванням додайте правило зупинки, наприклад бюджет або ліміт елементів.

Вправа на 15 хвилин

Оберіть пакетне завдання, наприклад підсумувати 10 файлів у теці. Запустіть його через subagent або workflow на вашій типовій model і запишіть токени та час. Потім задайте для CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL дешевшу model і повторіть запуск. Порівняйте обидва результати та напишіть нотатку з трьох рядків про вартість і якість.
