Claude Platform release notes

  • We're expanding which refusals are billed to include refusals that arrive before any output when stop_details.category is "bio", "frontier_llm", or "reasoning_extraction", the categories where we measure low volumes of false positives. Mid-stream refusals were already billed. The newly billed refusals are charged like any other request, at the rates of the model that ran it.
  • Cache diagnostics is out of beta on the Claude API and no longer requires the cache-diagnosis-2026-04-07 beta header. Include the diagnostics object on a Messages request to opt in; requests that still send the header work as before. Responses from POST /v1/messages now always include the diagnostics field, which is null when the request did not include the diagnostics object.
  • We've launched Claude Opus 5.5 (claude-opus-5-5), a model for long-running agentic coding and knowledge work. It has a 1M token context window by default, 128k max output tokens, and always-on adaptive thinking, at $4 / $20 USD per MTok (Claude Opus 5 is $5 / $25).
  • On Claude Opus 5.5, thinking can't be disabled: thinking: {"type": "disabled"} and thinking: {"type": "enabled", ...} return a 400 error. Omit the thinking field and control thinking depth with the effort parameter. tool_choice types any and tool also return a 400 error, as on Claude Fable 5.1; use auto with strict tool use.
  • Fast mode (research preview) is available for Claude Opus 5.5 on the Claude API.
  • Tools can now be defined inside a mid-conversation system message, in beta on the Claude API with the inline-tools-2026-09-15 beta header.
  • For cache diagnostics, a response to a request that sends the cache-diagnosis-2026-04-07 beta header now always includes the diagnostics field. The field is null when the request did not include the diagnostics object. Previously the field was omitted in that case.

Claude Agent SDK (Python) releases

  • v0.2.158: verbatim_prompts option: Added ClaudeAgentOptions.verbatim_prompts (default False). When True, user messages are delivered to the CLI exactly as written — no @path file expansion and no slash-command dispatch. This prevents untrusted text inlined into prompts from triggering unintended file reads or command execution. Works with query(), ClaudeSDKClient.connect(), and ClaudeSDKClient.query() for both string and async-iterable prompts.

Quoting Thariq Shihipar

Claude Code 2.1.277+ supports AGENTS.md as a fallback instruction file when CLAUDE.md doesn't exist. This feature builds on Claude Code mods, a customization framework that lets you modify the Claude Code harness behavior. The AGENTS.md support is itself a built-in mod, with capability to create custom mods.

Create AGENTS.md in a project folder without CLAUDE.md to test instruction loading in Claude Code.

Add multi-agent teams under latency pressure and budgets cookbook (#885)

A cookbook pattern demonstrates building lead-and-helpers agent teams that coordinate within a shared wall-clock budget. Two approaches included: time-aware prompting and explicit latency budgets on the timing mechanism. Useful for systems where multiple agents must cooperate under performance constraints.

Review the cookbook to understand how to structure agent prompts and budget tracking for coordinated multi-agent workflows.

Tag cookbook agents with anthropic_cookbook metadata (#886)

Managed Agents notebooks now pass metadata tagging each agents.create call with its cookbook source (format: lowercase repo/name). Sessions inherit the tag automatically. API validation ensures only properly formatted tags persist. Test coverage added to verify every agent creation carries the correct attribution tag.

Add metadata={"anthropic_cookbook": "claude-cookbooks/notebook-name"} to agents.create calls in your notebooks.
