Тенденції тижня

Claude Code дедалі більше перетворюється на програмовану платформу: моди отримують багатші дані для hooks, API вибору та повноцінний запускач тестів, а hooks навчаються розрізняти subagents і основну сесію. Керування сесіями рухається в бік іменованих тривалих завдань із attach і logs. Конкуренти відкривають можливості рев'ю та агентів для скриптів: GitHub надає code review від Copilot через API. Локальні середовища на кшталт Ollama додають вузькі моделі ухвалення рішень і декларації можливостей. Cowork від Anthropic переносить виконання в хмару.

Моди отримали офлайн-запускач тестів: claude plugin test

Що з'явилося

Документація Claude Code тепер описує claude plugin test: команда завантажує мод, запускає події через його hooks, підміняє виклики model і store та повідомляє про успіх або невдачу. Сесія, вхід в обліковий запис і мережа не потрібні.

Що змінилося з минулого випуску

Випуск 2026-10-02: Спробувати · Невідомо · відкритих багів: невідомо · виправлень після релізу: 0. Тепер: Впроваджувати · Невідомо · відкритих багів: невідомо · виправлень після релізу: 0.

Чому це важливо

Раніше моди перевіряли, завантажуючи їх у живій сесії. Тести, які запускають tool.call або command.run і перевіряють результат, виявляють регресії раніше, а ненульовий код виходу при невдачі добре підходить для CI.

Можливості

Навчайте написання модів за допомогою поетапних вправ, що виконуються офлайн. Передавайте клієнтам моди разом із набором тестів. Підміняйте $.model.complete, щоб детерміновано тестувати логіку обробки промптів без витрат токенів.

Як використати

Створіть файл із суфіксом .test.ts у каталозі plugin, імпортуйте test і expect з claude-code/testing, зареєструйте заглушки через on('tool.call', ...), запускайте події викликом $.tool.call(...), а потім виконайте claude plugin test у каталозі мода. У кожному файлі має бути щонайменше один test().

Урок тижня

Тестування hooks без сесії: заглушки та згенеровані події

Hook — це функція, що реагує на подію, тож її можна тестувати як будь-яку функцію: передати їй подію й перевірити результат. Набір для тестування модів робить це за вас. Ваш тест отримує $, який виконує роль Claude Code. Виклик $.tool.call({ tool: 'Bash', command: 'ls' }) запускає подію через hooks вашого мода й повертає те, що вони відповіли. Другий аргумент, on, реєструє заглушки, які відповідають там, де ваш мод зазвичай залежить від Claude Code, наприклад tool.call, store.get або $.model.complete. Нічого реального не виконується: ні інструмент, ні model, ні мережа. Це дає детерміновані тести для логіки, яку було незручно перевіряти вручну. Шаблон такий: підготувати, виконати, перевірити. Налаштуйте заглушки, запустіть одну чи кілька подій, потім перевірте повернений текст або стан. Перевіряйте одну поведінку в одному тесті й називайте тести реченнями. Оскільки claude plugin test завершується зі статусом 1 при невдачі, той самий набір можна запускати в CI. Прості допоміжні функції вашого мода можна імпортувати й тестувати модульно без набору. Поєднайте це з новим agentId у tool.check: напишіть один тест із подією основної сесії та один із подією subagent і перевірте, що політика відрізняється.

Вправа на 15 хвилин

Візьміть будь-який мод із hook-командою. Додайте tests/x.test.ts, імпортуйте test і expect з claude-code/testing, підмініть tool.call так, щоб він повертав { result: 'ok' }, викличте двічі $.tool.call, виконайте команду через $.command.run і перевірте answer.text. Запустіть claude plugin test, потім навмисно зламайте мод і переконайтеся, що статус виходу дорівнює 1.
