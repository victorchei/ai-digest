Тенденції тижня

Інструменти для агентів зміщують фокус із можливостей на контроль. Claude Code отримав hooks із блокуванням у разі збою (fail-closed), налаштування effort для кожного subagent і обмежені повторні спроби, а GitHub зробив локальну пісочницю загальнодоступною. Models і далі розділяються на рівні: Haiku 5.5 приносить контекст 1M на рівень для великих обсягів і низької затримки, з доплатою за понад 100k токенів. Віддалений нагляд за локальними агентами поширюється (iOS-застосунок Cursor), а типові налаштування протоколу під MCP servers змінюються, тож фіксуйте версії того, від чого залежите, і тестуйте їх.

Головне

Hooks тепер можуть блокувати дію у разі збою завдяки onFailure block

Що з'явилося

Command і HTTP hooks приймають onFailure: "block": якщо hook не вдається запустити, він перевищує час очікування або завершується з неочікуваним кодом, дія блокується. Окремо теги <system-reminder> у виводі hook тепер екрануються, перш ніж потрапити до Claude.

Чому це важливо

Досі зламаний захисний hook мовчки пропускав дію, тож надійність такого hook залежала лише від його скрипту. Режим fail-closed робить hooks справжнім механізмом примусового контролю. Екранування закриває шлях, яким вивід hook міг видавати себе за системні інструкції.

Можливості

Створюйте надійні запобіжники: блокуйте запис у захищені шляхи, вимагайте запуск тестів перед комітом, обмежуйте команди розгортання. Для навчання це наочний приклад різниці між проєктуванням fail-open і fail-closed. Заплановані запуски без нагляду отримують безпечнішу базу.

Як використати

Додайте "onFailure": "block" до запису hook у налаштуваннях для hooks, що захищають щось ризиковане (секрети, руйнівні команди оболонки). Потім перевірте, навмисно зламавши скрипт, наприклад неправильним шляхом або таймаутом, і переконайтеся, що дію заблоковано. Не вмикайте це для hooks, які лише пишуть журнал або надсилають сповіщення. Якщо ваш hook додавав текст <system-reminder>, перевірте, як він тепер надходить.

Claude Haiku 5.5: контекст 1M для великих обсягів роботи

Що з'явилося

Claude Haiku 5.5 (claude-haiku-5-5) — це model, налаштована на роботу з великими обсягами та чутлива до затримок. Вона має вікно контексту 1M токенів, максимальний вивід 128k і адаптивне мислення з параметром effort. Доступна в Claude API та у великих хмарах.

Чому це важливо

Дешевий і швидкий рівень тепер отримує довгий контекст і адаптивне мислення, які раніше були лише у більших models. У документації зазначено, що промпти понад 100,000 токенів на Haiku 5.5 коштують дорожче, на відміну від інших models з 1M, і що вона за замовчуванням зберігає попередні блоки мислення в контексті.

Можливості

Дешеві subagents, масова класифікація, сортування журналів чи документів, навчальні боти, яким потрібні швидкі відповіді. Роботу з довгим контекстом можна запускати на нижчому рівні, якщо стежити за цінами понад 100k.

Як використати

Перемкніть скрипт для великих обсягів або subagent на claude-haiku-5-5 і порівняйте якість та затримку з вашою поточною model. Налаштуйте мислення параметром effort. Скористайтеся API підрахунку токенів, щоб побачити, чи промпти перевищують 100k токенів, перш ніж на це зважуватися. Точні тарифи дивіться на сторінці цін.

Subagents отримали налаштування effort і ліміт попереднього завантаження 32 skills

Що з'явилося

Інструмент Agent має новий параметр effort, щоб Claude запускав subagent із вибраним рівнем зусиль. Subagents тепер попередньо завантажують щонайбільше 32 skills із поля skills, кожен по одному разу; через інструмент Skill вони все одно можуть викликати решту.

Чому це важливо

Зусилля на міркування можна витрачати там, де вони окупаються: низькі для пошуку й підсумовування, високі для рев'ю. Ліміт не дає великому списку skills заповнити контекст subagent на старті, а решта лишається доступною на вимогу.

Можливості

Оркестратори, що поєднують дешевих швидких виконавців з кількома глибокими рев'юерами. Бібліотеки skills можуть рости, не роздуваючи кожен subagent. Добрий матеріал для навчання проєктуванню агентів з урахуванням вартості.

Якщо список skills у subagent перевищує 32, перенесіть найважливіші skills на початок і покладайтеся на інструмент Skill для решти. Допустимі значення effort дивіться в документації.

Урок тижня

Робіть автоматизації такими, що блокують дію при збої та мають межі

Агенти без нагляду підводять двома способами: пропускають щось, коли ламається перевірка безпеки, або зависають в очікуванні. Зміни цього тижня дають по засобу контролю для кожного випадку. З onFailure: "block" на command або HTTP hook, якщо hook не вдається запустити, він перевищує час очікування або завершується з неочікуваним кодом, дію блокується. Без цього одруківка у вашому захисному скрипті може обернути його на відсутність захисту взагалі. З CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS режим повторних спроб без нагляду перестає вичікувати помилки 429 і 529 після обраного вами ліміту. Застосуйте правило: для кожного hook вирішіть, чи він щось захищає (fail closed), чи лише спостерігає (fail open). Для кожного запланованого завдання визначте найдовший допустимий час роботи й зробіть обмеження очікування меншим за нього. Пам'ятайте також, що вивід hook — це текст, який читає Claude: теги <system-reminder> у ньому тепер екрануються, тому не покладайтеся на hooks як на спосіб видавати себе за системні повідомлення. Перевіряйте збої навмисно, бо захист, який ви ніколи не бачили в разі збою, — це припущення.

Вправа на 15 хвилин

Виберіть один hook, що щось захищає, наприклад блокує редагування захищеного шляху. Додайте onFailure: "block". Зламайте скрипт, указавши неіснуючий файл, і переконайтеся, що дію заблоковано. Потім виправте. Для одного запланованого завдання задайте CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS зі значенням менше за ваше вікно запуску.

Claude Platform release notes

  • We've lowered the price of prompt cache reads on Claude Sonnet 5.5 from $0.20 USD to $0.10 USD per million tokens: 0.05x the base input price instead of 0.1x. Cache writes and all other prices are unchanged. See Prompt caching pricing.
  • We've launched Claude Haiku 5.5 (claude-haiku-5-5), our most capable model tuned for high-volume and latency-sensitive work. It has a 1M token context window, 128k max output tokens, and adaptive thinking with the effort parameter.
  • Code written for Claude Haiku 4.5 can break on Claude Haiku 5.5. Manual extended thinking (budget_tokens) returns a 400 error, and adaptive thinking is on by default, so a response can begin with thinking blocks. The same text also counts as more tokens. See the migration guide. For model-specific prompting patterns, see Prompting Claude Haiku 5.5.
  • The Python and TypeScript SDKs now include classes, in beta, for the browser use tool and the computer use tool. You subclass one and write one method per tool against your own browser or desktop automation. The SDK runs the tool loop, the URL and file policies you set for the browser, and your approval callback.
  • Claude Max and Team plans now include monthly API credits. To learn how to claim them, see API credits for Max and Team plans.
  • In Claude Managed Agents, a cloud environment with limited networking now also applies its allowed_hosts to the web_search and web_fetch tools. A web_fetch call for a URL on a host that allowed_hosts does not match returns a url_not_allowed error result to the agent. web_search omits results from such hosts.
  • With limited networking, creating a session fails with a 400 error when an enabled web tool's allowed_domains has an entry not within allowed_hosts. So does a session update that adds such an entry. An allowed_hosts entry matches one exact host unless it starts with *., so docs.example.com is not within ["example.com"].
  • In Claude Managed Agents, the web_fetch tool now fetches only URLs that have already appeared in the session, for example in the text of a user message, in a web_search result, or in a page that web_fetch returned earlier. This reduces the risk of data exfiltration.
  • We've added capabilities.server_tools to the Models API. GET /v1/models and GET /v1/models/{model_id} now report whether each model accepts the web search and code execution tools. To check whether a model accepts the code execution tool, read capabilities.server_tools.code_execution. The top-level capabilities.code_execution reports whether code can call your request's other tools. See Using the Models API.
  • We've added capabilities.thinking.types.disabled to the Models API. GET /v1/models and GET /v1/models/{model_id} now report whether each model accepts thinking: {type: "disabled"}, which turns thinking off. See Using the Models API.
